# 短链接系统接口文档（阶段1）

> 服务地址：http://localhost:8080　包名：com.bq.shortlink　数据格式：JSON（UTF-8）

## 1. 通用约定

### 1.1 基础约定

| 项目 | 约定 |
| --- | --- |
| Base URL | http://localhost:8080 |
| 业务接口前缀 | /api/shortlink |
| 请求编码 | UTF-8 |
| 请求体类型 | application/json（POST 接口必须携带该请求头） |
| 时间格式 | ISO-8601，例如 2026-10-17T23:00:00 |
| 短码字符集 | 0-9、a-z、A-Z，长度 9-10 位，区分大小写 |

### 1.2 统一返回

业务接口统一返回 `Result{code, msg, data}`：`code` 为业务码（200 成功，非 200 失败），`msg` 为提示信息（成功时为"成功"），`data` 为业务数据（失败时为 null）。

```json
{
  "code": 200,
  "msg": "成功",
  "data": null
}
```

### 1.3 业务码表

| code | 含义 | 说明 |
| --- | --- | --- |
| 200 | 成功 | 创建、查询成功 |
| 50000 | 系统异常 | 未捕获异常、数据库异常等 |
| 50001 | 长链接为空 | longUrl 缺失、空串或全空白 |
| 50002 | 长链接格式错误 | 不是 http:// 或 https:// 开头 |
| 50003 | 短链接不存在 | 详情查询按 shortCode 查不到记录 |

注意：`/api/**` 业务接口的 HTTP 状态始终为 200，业务结果只看 code，不要用 HTTP 状态码判断成功与否。

### 1.4 接口一览

| 方法 | 路径 | 说明 | 成功 HTTP 状态 |
| --- | --- | --- | --- |
| POST | /api/shortlink/create | 创建短链接 | 200 |
| GET | /api/shortlink/{shortCode} | 查询短链接详情 | 200 |
| GET | /{shortCode} | 短码 302 跳转 | 302 |
| GET | / | 极简蓝白测试页 | 200 |

## 2. 创建短链接

POST /api/shortlink/create

请求头：

| 请求头 | 值 |
| --- | --- |
| Content-Type | application/json |

请求体参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| longUrl | string | 是 | 原始长链接，必须以 http:// 或 https:// 开头；字段上限 2048 字符 |
| expireDays | int | 否 | 过期天数；不传、传 null 或小于等于 0 表示永不过期 |

请求示例：

```json
{
  "longUrl": "https://www.baidu.com",
  "expireDays": 7
}
```

成功响应（HTTP 200）：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "shortCode": "1aB3dK9xYz",
    "shortUrl": "http://localhost:8080/1aB3dK9xYz",
    "longUrl": "https://www.baidu.com",
    "visitCount": 0,
    "createTime": "2026-10-17T23:00:00",
    "expireTime": "2026-10-24T23:00:00"
  }
}
```

其中 shortCode 为 62 进制短码（约 10 位，全局唯一），shortUrl 由服务地址与 shortCode 拼接，visitCount 新建时为 0，expireTime 为 null 表示永不过期。

错误响应（HTTP 200，code 非 200），两个示例：

```json
{"code": 50001, "msg": "长链接不能为空", "data": null}
{"code": 50002, "msg": "长链接格式错误", "data": null}
```

curl 示例：

```bash
curl -X POST http://localhost:8080/api/shortlink/create \
  -H "Content-Type: application/json" \
  -d '{"longUrl":"https://www.baidu.com","expireDays":7}'
```

## 3. 查询详情

GET /api/shortlink/{shortCode}

请求头：无特殊要求。

路径参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| shortCode | string | 是 | 要查询的短码，区分大小写 |

成功响应（HTTP 200）：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "shortCode": "1aB3dK9xYz",
    "shortUrl": "http://localhost:8080/1aB3dK9xYz",
    "longUrl": "https://www.baidu.com",
    "visitCount": 12,
    "createTime": "2026-10-17T23:00:00",
    "expireTime": null
  }
}
```

短码不存在时仍返回 HTTP 200，业务码为 50003：

```json
{
  "code": 50003,
  "msg": "短链接不存在",
  "data": null
}
```

curl 示例：

```bash
curl http://localhost:8080/api/shortlink/1aB3dK9xYz
```

## 4. 短码跳转

GET /{shortCode}

请求头：无特殊要求。路径只接受字母与数字，正则 `[0-9a-zA-Z]+`。

成功：HTTP 302，响应头 Location 为原始长链接，无业务响应体。

```http
HTTP/1.1 302 Found
Location: https://www.baidu.com
```

短码不存在或已过期：HTTP 404，无响应体。

```http
HTTP/1.1 404 Not Found
```

curl 示例：

```bash
# 查看跳转状态与 Location
curl -i http://localhost:8080/1aB3dK9xYz

# 跟随跳转
curl -L http://localhost:8080/1aB3dK9xYz
```

说明：本接口不使用统一返回结构，浏览器直接访问时按 302/404 处理；阶段1 不做访问统计，visitCount 保持为 0（阶段3 接入统计后才会在跳转时自增）。

## 5. 测试页

GET /

请求头：无特殊要求。返回 HTTP 200，Content-Type 为 text/html，页面来自静态文件 `src/main/resources/static/index.html`。

页面说明：

- 极简蓝白配色，文字为黑色，按钮不使用蓝色（浅灰或白底描边），每个按钮都绑定了点击事件。
- 提供长链接输入框、过期天数输入框、"生成短链接"与"填入示例"按钮；创建结果区提供"打开短链接（302 跳转）""复制短链接""查询该短码详情"按钮。
- 提供短码输入框与"查询详情""直接访问短码"按钮，结果区展示短码、短链接、长链接、访问次数、创建时间与过期时间。
- 页面通过 fetch 调用 `/api/shortlink/create` 与 `/api/shortlink/{shortCode}`，展示 code、msg 与 data。

## 6. 幂等说明

- 同一个 longUrl 且已有未过期记录时，再次创建不会新增记录，直接返回已有记录的 shortCode 与其详情。
- 幂等以 longUrl 字符串完全相等为准：大小写不同、末尾斜杠不同都视为不同链接。
- 再次创建时传入的 expireDays 被忽略，返回记录的过期时间以首次创建为准。
- 已过期的记录不作为幂等命中，会在 t_short_link 中新增一条记录并生成新短码。
- 阶段1 为"先查后插"的弱幂等，没有 long_url 唯一索引兜底；并发同时创建同一 longUrl 时可能产生多条不同短码的记录，量小场景可接受。

## 7. 过期说明

- 不传 expireDays、传 null 或小于等于 0：expire_time 为 NULL，永不过期。
- 传 expireDays=N（N 大于 0）：expire_time = 创建时间 + N 天，按 DATETIME 存储，精度到秒。
- 过期后短码跳转返回 HTTP 404；详情接口仍可查到该记录（含已过去的 expireTime），便于页面展示与排查。
- 过期记录不会自动删除，阶段1 没有清理任务；如需继续使用同一长链接，重新创建即可获得新短码。
- 服务端不使用 JVM 缓存，修改数据库中的 expire_time 后下一次请求立即生效，便于测试。

## 8. 验收清单

1. 启动项目，控制台无报错，端口 8080 可访问；即使本机未启动 Redis 也能正常启动。
2. GET / 返回 200 与蓝白测试页，页面中文显示正常，按钮均有点击响应。
3. 创建接口返回 code=200，shortCode 为 9-10 位字母数字、长度不超过 10、全局唯一，shortUrl 可直接拼接访问。
4. 同一 longUrl 连续创建两次，返回的 shortCode 相同。
5. 浏览器访问 shortUrl 返回 302 并跳转到原长链接；随后查询详情，visitCount 仍为 0（阶段1 不统计访问，阶段3 接入后才会自增）。
6. 访问一个不存在的随机短码，例如 http://localhost:8080/zzzz9999，返回 404。
7. 查询不存在的短码详情，返回 HTTP 200 且 code=50003。
8. 传入空 longUrl 返回 50001；传入 ftp://example.com 返回 50002；两者 HTTP 状态均为 200。
9. 手动把某条记录的 expire_time 更新为过去时间，跳转返回 404，详情仍能查到。
10. 重复点击创建按钮，结果一致，不产生重复短码。
11. 应用启动后可直接运行 `powershell -ExecutionPolicy Bypass -File scripts/verify-phase1.ps1` 自动跑完上述主要用例。

## 9. 常见问题

- **访问短码一直 404**：短码不存在、已过期，或复制时带了空格/换行；先调用详情接口确认记录与 expire_time。
- **POST 创建返回 415 或 50000**：缺少 `Content-Type: application/json`，或请求体不是合法 JSON；该异常可能被全局兜底转成 50000，补上请求头即可。
- **启动报数据库连接失败**：检查 MySQL 是否启动、是否执行过 `sql/init.sql` 建库建表、application-local.yml 账号密码、端口 3306；该文件被 .gitignore 忽略，需从 application-local.yml.example 复制填写，连接串使用 serverTimezone=Asia/Shanghai 与 allowPublicKeyRetrieval=true。
- **端口 8080 被占用**：`netstat -ano | findstr :8080` 找到 PID 后结束进程，或修改 server.port 并同步调整 Base URL。
- **短码不是 6 位**：正常，短码由雪花 ID 转 62 进制得到，当前为 10 位左右；62^6≈568 亿只是容量参考，阶段1 不追求 6 位。
- **HTTP 200 但 code 不是 200**：这是约定，业务接口 HTTP 状态固定 200，只看 Result.code；跳转接口与静态页除外。
- **Windows PowerShell 下 curl 异常**：curl 是 Invoke-WebRequest 的别名，请改用 `curl.exe`，例如 `curl.exe -X POST ...`。
- **测试页按钮没反应**：打开浏览器控制台看报错，确认后端已启动、接口地址为 http://localhost:8080；按钮事件应在页面加载后绑定。
